# 阶段 9 · C0 ID 基线

## 结构与适配

C0-ID-only-adapted 为两个项目共用的 ID 建模起点，不包含多模态向量。采用十个离散字段的 embedding、短历史目标注意力、长历史目标注意力和点击率预测 MLP。

|组件|配置|
|---|---|
|离散字段|用户及五项属性、目标商品/类目/城市/省份|
|Embedding|各字段 16 维，商品与历史共享、类目与历史共享|
|短历史|末尾 50 个位置；商品和类目拼接后的目标注意力|
|长历史|末尾 200 个位置；独立参数的目标注意力|
|注意力|线性 Q/K、按维度缩放点积、masked softmax、历史向量加权和|
|预测塔|十项 embedding 与两个兴趣向量拼接；128、64 隐层 ReLU，输出一个 logit|
|损失|BCEWithLogitsLoss，label_0[1] 为点击标签|

该结构为公共研究骨架适配，不等同于 CIKM 私有生产网络、DIN 的局部激活结构或 MUSE 的完整模型。两个兴趣分支均不引入多模态信息；MUSE 的检索改动须在匹配公共结构后比较。

## 训练协议

配置见 [c0.json](../configs/c0.json)。seed=42，batch=32，训练一轮；按固定随机顺序遍历全部训练曝光，末批保留。

Embedding 使用 SparseAdam，稠密参数使用 AdamW，两者学习率均为 0.001，weight_decay=0。后者显式偏离可能含默认衰减的参考配置，作为本项目冻结的适配记录。稀疏梯度减少更新开销，但 SparseAdam 的状态仍按完整词表分配。

PAD 与 OOV 初始向量为零；训练词表内全部训练 ID 已知，因此 OOV 不会从训练未知 ID 获得有效更新。验证侧的用户 OOV 条件须在结果解释中保留。

```powershell
python scripts/train_c0.py --store ../shared-feature-store-v1 --config configs/c0.json --output-dir ../c0-seed42-epoch1
```

仅训练和验证数据被实例化。指标使用完整验证集合，GAUC 按独立用户行号聚合，避免将映射成同一个 OOV 的用户错误合并。预测文件保留标签、源行号和用户行号。最终 checkpoint 保存模型权重；当前入口不支持从优化器状态恢复中断训练，中断后需从新运行目录重新开始。

## 资源检查

20 步资源检查使用 640 条训练曝光，峰值 allocated 为 2,830.75 MiB、reserved 为 2,840 MiB；参数更新与保存重载一致性通过。资源检查的验证成绩只用于链路诊断，不作为完整一轮结果。机器记录见[资源报告](../reports/c0-resource-probe.json)。

23 项测试通过，新增全空历史、稀疏梯度、双分支梯度连接及 mask 不变性验证。

## 结果边界

本阶段只运行一个种子和一个 ID 基线，不能据此证明多模态改进有效。后续方法共享本配置的数据、评估与公共网络；变化项须单独声明。测试集不参与本阶段选择。

## 常数参考

训练集点击率为 13.6351%。以该常数对验证集预测，AUC=0.5、GAUC=0.5、LogLoss=0.396982。该参考不使用验证标签拟合参数，见[参考结果](../reports/c0-prior-reference.json)。模型收益需在完整验证结果产生后比较，不能以在线累计训练损失替代。
