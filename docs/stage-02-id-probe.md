# 阶段 2 · 真实数据 ID 基线工程验证

## 目标与范围

在固定训练分片上验证原始 ID 到张量、目标注意力、点击损失、参数更新与模型保存重载的完整链路。此实现为 C0 的工程原型，仅使用商品 ID；用户、类目及公共短历史分支尚未接入，不能作为正式 C0 对照。

## 数据与结构

输入为阶段 1 生成的 1,890 行 probe，264 次点击。原始有符号商品 ID 作为不透明标识处理，负数仍有效。训练目标和选中历史共同构建排序稳定的词表，索引 0 为 padding、1 为 OOV，其余为已知商品。词表仅来自当前训练分片。

历史保留末尾 200 个位置并左侧补齐，遵循参考代码；原始时间方向尚未通过时间戳独立验证。有效 mask 由 padding 标记构造，未知商品与 padding 分开。当前分片没有原始零值历史，空历史和屏蔽行为通过构造测试验证。

模型采用 16 维共享商品 embedding；目标与历史分别线性投影后点积，masked softmax 生成权重，历史 embedding 加权和与目标 embedding 拼接，经过 32 维隐藏层输出一个 logit。BCEWithLogitsLoss 使用 label_0[1] 作为点击标签。该结构是本地工程适配，尚未冻结为跨项目公共骨架。

## 运行

在仓库根目录，使用已验证 bootstrap 环境对应的 Python：

```powershell
python scripts/train_id_probe.py --input ../taobao-mm-probe/probe.parquet --output-dir ../id-probe --report reports/id-probe.json
python -m unittest discover -s tests -v
```

路径可根据数据实际位置调整。默认 seed=42、batch=32、历史长度=200、epochs=3，Adam 学习率为 0.001。脚本设置确定性 CUDA 计算所需配置，未检测到 CUDA 时明确退出。仅支持最多 4,096 行工程样本，不作为全量流式训练入口。
