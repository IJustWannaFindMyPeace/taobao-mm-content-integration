# 共同主实验规模：5% 用户队列

## 决策

两个项目本轮共同主实验采用既有 5% 用户队列及共享特征存储。训练曝光 3,052,475 条、验证 768,773 条；保留测试队列 923,211 条尚未进行模型评估。数据清单 SHA-256 为 `7dd761c48f61b3ae219922f8387f6026eb6eb011ef6ef8050bb1472a52593f59`。这是证据范围与资源成本的折中，不是硬件最大容量或统计充分性的证明。

同组主对照固定队列、划分、词表、内容向量、评估方法与随机种子集合。batch、学习率等共同下游训练协议尚未冻结；改变训练协议后，需要统一重跑相关主对照，旧协议证据单列。MAKE 预训练阶段另记轮数与计算成本。

## 扩容实测

容量扫描重新校验两个训练源文件 SHA-256，仅读取用户 ID 与历史商品 ID，不读标签或测试文件。7.5% 和 10% 使用与现有队列相同的哈希规则、训练/验证用户划分，完整匹配选中训练用户历史；耗时 761 秒。

|用户队列|训练用户|训练曝光|历史不同商品|商品权重与两份 Adam 状态下限|
|---|---:|---:|---:|---:|
|7.5%|416,305|4,564,733|54,393,613|9.73 GiB|
|10%|554,854|6,083,300|64,315,211|11.50 GiB|

估算固定 16 维 FP32，每个商品需要权重及两份优化器状态，共 192 字节。下限未包含仅作为目标出现的商品、其他字段、梯度、激活、CUDA 和分配器开销。当前 5% 的全部字段权重与状态约 7.72 GiB，完整 MUSE 大 batch 运行仍需额外显存。

10% 几乎没有剩余空间，不作为当前设备和实现的主配置。7.5% 可能在某些设置下运行，但没有完整模型实测，不能称为不可能；其静态下限已明显压缩共同协议的余量。本轮不为扩容缩小向量维度、改词表或不断降低 batch，也不继续搜索硬件极限。容量报告是下限分析，不是 OOM 试验。

## 5% 对研究问题的支持与不足

训练频次分组的验证曝光为：零次 137,978、一次 84,277、2–5 次 170,886、6–20 次 180,136、21–100 次 137,301、101 次以上 58,195。已有三个种子的整体与分组证据支持研究内容融合；这些数量不等于预先功效分析，也不代表冷启动原文实验已经复现。

新增历史长度诊断按公开 1000 位置中非 padding 行为数分组，重复行为和未知 ID 均计数。长度为检索前可用历史，不是真实终身行为总数。

|可用历史长度|验证曝光|用户数|正样本|
|---|---:|---:|---:|
|0|392|63|35|
|1–50|1,786|264|175|
|51–200|4,080|535|552|
|201–500|6,263|750|811|
|501–1000|756,252|67,818|102,870|

98.37% 的验证曝光位于最后一组，因此当前整体结果主要代表长历史用户。完整内容检索组合从 L200 扩到 L1000，在 501–1000 组的三个种子 AUC 差分别为 +0.003615、+0.001425、+0.003267；201–500 组三个种子也为正。其他组混合或样本很少，不作普遍收益断言。分组结果是描述性结果，未计算分组置信区间。

即使某个用户历史不超过 200，两种长度训练出的模型也可能预测不同，因为全体训练用户的历史输入改变了共同参数；不能把该组差异解释为该用户新增了历史。

目标内容缺失仅 13 条曝光、2 条正样本，不能支持可靠效果推断。扩大整体队列不会自动保证这些稀少场景获得充足样本；本轮明确限制结论，不用小组点估计补齐故事。若以后增加独立稀有场景诊断，需另定抽样与评估口径，不能混入自然分布主表。

## 后续与重开条件

先完成共同训练方案确认、必要的多种子与敏感性对照，再冻结测试评估协议。只有发现关键假设的证据精度不足，且资源可行性已有明确方案时，才重新讨论更大队列；规模变更须两项目共同更新，不能让部分方法独享更多数据。
