# 两项目整体收尾审计

审计日期：2026-09-25。结论：**本轮正式下游比较的公共协议与测试口径已统一，未发现遗漏的正式模型或需要重训的数值问题。**“统一”不表示每种结构、历史长度和预训练预算都相同，也不表示所有能想到的扩展实验都已完成。

## 核验结果

|核验范围|结果|含义|
|---|---|---|
|两项目公共协议|通过|同一5%用户队列、内容表、划分、标签、batch=256、宽度16、学习率与资源约束|
|正式模型覆盖|54主模型＋73补充检查点全部纳入|127份模型记录，不等于127种独立方法；相同模型复用不能算独立证据|
|完整测试输入|127份预测逐行一致|均为923,211条曝光；标签、用户映射、原始源行与特征存储一致|
|独立指标重算|全部通过|另一套向量化秩统计实现重算AUC、GAUC、LogLoss；最大绝对差7.55×10⁻¹⁵|
|配对比较|66主比较＋93追加比较通过|基线/候选预测指纹、报告指标、差值运算、2000次bootstrap设置均一致|
|跨仓库报告|通过|主结果和追加结果的共享报告字节一致|
|冻结源码与数据|通过|原冻结源码、本次依赖和测试数组指纹保持一致|
|Git检出字节|37个冻结文件通过|明确换行规则，重新检出的文件匹配实验冻结哈希|

GAUC使用45,985位同时有正负标签的用户，对应700,297条曝光；其余用户不参与GAUC。AUC与LogLoss使用全部923,211条曝光。该口径在两项目中一致。

## 全部本地产物是否都有去向？

审计枚举了255个 `.pt` 文件。127个是正式下游模型，均有测试报告；另外128个明确分类如下，没有把无法解释的文件默认为“不重要”。

|其余产物|数量|为何不放入统一正式测试表|
|---|---:|---|
|早期batch=32探索模型|68|已由共同batch=256协议下的正式模型替代，保留历史探索证据|
|batch/学习率协议选择|11|用于验证阶段选择公共协议，不在看到测试后补选配置|
|资源或功能探针|17|短步数运行验证工程可行性，不代表完整研究实验|
|上游内容预训练检查点|27|用于学习内容分支与训练曲线；其对应最终下游模型已纳入测试|
|上游检索评分器|3|G1的中间训练阶段，对应最终推荐模型已测试|
|环境或预测辅助张量|2|不是正式模型|

这解释的是现有实验目录的覆盖，不是穷尽所有可能设计。中间预训练分支虽可另做独立预测实验，也不应无目的地塞进下游正式排行榜。

## 保留的差异与例外

- **主动研究的差异**：历史长度、K或多头候选预算、结构、预训练轮数和冻结策略保留差异。正式下游通常训练一轮；ID第3轮对照是显式例外。内容预训练采用独立批大小，不能冒充与下游同成本。
- **证据阶段不同**：主测试预先冻结；追加测试发生在主测试结果已查看之后。两者使用同一测试口径，但不能包装成同一次新盲测。分组分析仍是事后诊断。
- **ID第2轮**：原权重未保留，仅有验证过程证据。重新训练可以形成新实验，不能冒充已补测原第2轮；当前第1轮与第3轮测试对照已完成。
- **案例与过程诊断**：匿名检索案例固定在验证集；训练曲线与资源探针保持原用途。它们不因未改成测试案例而成为模型漏测。
- **资源证据**：并行外部负载影响本次耗时，不能用于受控速度排名；未发现由此产生的预测缺行或指标损坏。
- **原论文与数据限制**：固定内容向量不能代替SCL编码器训练或CLIP/OpenCLIP/I2I完整表示对照；公开历史上限1000，不支持原100K线上实验。5%不是硬件最大规模结论。

## 本次发现并修正的问题

1. **过期覆盖入口**：方法覆盖和实施路线仍把旧审计称为当前状态，并标注G1/G3、DIN/TWIN/MISS待完成。已更新为本地适配完成及其真实边界；有日期的历史报告保留原发现时点。
2. **源码换行与冻结哈希**：冻结时存在LF、CRLF及少量混合换行。若Git按机器默认规则转换，源码逻辑虽相同，原字节哈希可能不匹配。已增加逐文件 `.gitattributes`：纯换行文件固定检出方式，混合换行的历史文件按字节保存。37个冻结依赖均通过Git检出过滤后的哈希校验。没有修改本地模型逻辑、检查点或原冻结文件。

现有9项执行/比较契约测试与新增3项独立指标测试均通过；新增测试覆盖并列分数、单类别用户排除、曝光加权及随机分组。
