# TAOBAO-MM 数据定义与覆盖率核验

## 官方依据

核查日期：2026-09-12。来源为 [TAOBAO-MM 数据集官网](https://taobao-mm.github.io/) 与 [MUSE 官方仓库的数据配置说明](https://github.com/alimama-tech/MUSE#run-experiments)。处理数据固定于 revision `f185841b6e9612edd06f5112e06416f1bdf6c6d0`；当前官网描述与版本化数据分别记录。

|项目|官方说明|项目处理|
|---|---|---|
|训练/测试边界|按时间划分，约 76M / 23M 曝光|保留官方边界；用户互斥验证是训练集内部的额外适配|
|历史序列|每位用户最多 1,000 条商品及类目记录|保留原始序列，padding 与未知/缺失内容分开处理|
|商品属性|覆盖训练和测试目标商品|按商品键关联并校验基数|
|多模态表示|匿名 ID 与预计算 128 维 SCL 向量，不公开原始图文|使用固定 int8 表，不声称重训原始编码器|
|p90 覆盖|官网称目标商品全覆盖、历史商品约 90%；代码配置明确写为历史交互覆盖|统计去重商品、历史记录和曝光加权三种口径，分别报告|

官方 train/test 时间边界与序列内部顺序是两个问题。参考数据加载代码从末尾截取近期历史；原始曝光表没有逐条时间戳，因此不能仅靠本地表独立还原官方时间划分。历史特征表按用户组织，曝光通过用户 ID 关联；这不表示每条曝光都附有独立更新的历史快照。

字段逐项含义、模型输入列顺序与索引约定见[字段字典](dataset-fields.md)。

## 覆盖率分母

1. **去重商品覆盖率**：有内容的所需商品 ID 数 / 所需商品 ID 并集大小。阶段 7 的 69.01% 使用此口径，混合了目标与历史，不能直接对比官方 90%。
2. **用户历史记录覆盖率**：每位选中用户的非 padding 历史记录计一次，同一商品的重复行为保留。
3. **曝光加权历史覆盖率**：按用户在对应曝光集合中出现的次数，对其历史记录重复加权。
4. **目标曝光覆盖率**：目标有内容的曝光数 / 全部曝光数；同时记录缺失目标的去重数量。

子集、用户权重与去重方式不同，结果可能不同。验证官方全量声明还需要全量同口径统计；子集结果接近 90% 不能单独证明完全一致。

## 直接源表复核

核查脚本 [audit_content_coverage.py](../scripts/audit_content_coverage.py) 直接读取完整 SCL 源文件的商品键，独立于已提取向量子表核对目标和历史。源文件完整 SHA256 已在特征提取阶段验证。结果见 [content-coverage-audit.json](../reports/content-coverage-audit.json)。

```powershell
python scripts/audit_content_coverage.py --source ../taobao-mm-source/raw/scl_embedding_int8_p90.parquet --cohort-dir ../user-cohort-v1-010 --history-dir ../user-cohort-v1-010-histories --report reports/content-coverage-audit.json
```

目标缺失与官方目标全覆盖描述之间的差异单独保留。在原因确认前，不删除这些曝光，也不将差异直接归结为 p90 的正常截断。

## 1% 子集核验结果

|集合|用户历史记录覆盖|曝光加权历史覆盖|缺失目标曝光 / 去重目标|
|---|---:|---:|---:|
|训练|88.95%|90.83%|12 / 6|
|验证|88.85%|90.75%|1 / 1|
|测试|89.15%|91.00%|6 / 4|

完整源表键复核仍得到 12、1、6 条缺失目标曝光，与提取子表一致，排除了仅由当前子表过滤遗漏导致的解释。差异原因尚未确定；不将官网的全量覆盖声明改写为实测已满足。
