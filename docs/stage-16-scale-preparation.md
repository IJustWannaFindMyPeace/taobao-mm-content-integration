# 阶段 16：5% 数据准备与资源验证

本阶段扩大共同数据规模，不使用验证指标选择子集，也不改变原有数据划分与标签契约。5% 是候选规模，最终采用与否取决于特征存储验证和训练资源实测。

## 已完成的数据检查

|划分|曝光记录|商品属性覆盖率|
|---|---:|---:|
|训练|3,052,475|100%|
|验证|768,773|100%|
|保留测试|923,211|100%|

属性关联前后曝光数量与源行顺序一致，见[属性报告](../reports/item-join-050.json)。

历史提取按用户去重：训练与验证合计 347,235 位用户，保留测试 82,542 位用户。所选用户均在对应官方历史表中找到唯一记录；商品与类别序列长度一致，无空历史字段或空元素。这里的 100% 表示用户记录匹配率，不表示每条历史行为都有内容向量。见[历史报告](../reports/history-extraction-050.json)。

两份历史表扫描耗时合计约 258 秒，进程峰值工作集约 11.68 GiB；耗时不含前置源文件校验。扫描通过不等于模型训练资源检查通过。

## 待完成的资源门槛

1. 提取所选历史和目标所需的固定内容向量，独立记录目标覆盖率与唯一商品覆盖率。
2. 构建仅由训练目标与训练用户历史确定的 ID 词表，生成特征存储，并核验标签、源行、ID 映射及历史读取。
3. 对完整候选词表执行 C6（历史 200）和 R4（历史 1000、K=50）至少 200 步训练资源测试。

工程目标仍为分配显存不超过 9 GiB、进程峰值工作集不超过 24 GiB。资源测试不得使用未训练模型的预测指标作为效果证据；C6 结构探测可使用随机冻结内容参数，但正式实验必须重新按该数据规模预训练并验证检查点来源。

本次记录时，内容提取、特征存储及 GPU 资源测试尚未全部完成。未启动该规模的正式训练，未评估保留测试集，也未确认最大可用数据规模。
