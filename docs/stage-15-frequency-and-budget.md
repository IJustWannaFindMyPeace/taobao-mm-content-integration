> 文档性质：阶段记录／历史协议。本文中的规模、配置、验证结果及待办状态属于记录时点；当前结果以[主测试](final-test-results.md)、[补充测试](supplementary-test-results.md)和[覆盖说明](current-reproduction-status.md)为准。

## 训练频次诊断

频次仅由当前 1% 训练曝光中的原始目标商品 ID 统计，固定分组为 0、1、2–5、6–20、21–100、101+。验证标签不参与分组，OOV 商品不会合并为一个 ID。频次为 0 只表示未作为该训练子集的目标曝光出现，不能证明商品新建、没有历史交互或属于完全冷启动。

以下差值为候选 AUC 减基准 AUC，均使用同一组验证记录：

|训练曝光频次|验证曝光数|点击数|C6−C0 AUC|R4−R1 AUC|
|---|---:|---:|---:|---:|
|0|62283|9247|+0.026818|+0.021259|
|1|24670|3571|+0.026448|+0.009954|
|2–5|32563|4384|+0.015818|+0.011866|
|6–20|21007|2480|+0.015808|+0.009255|
|21–100|9968|850|+0.005088|+0.004476|
|101+|1456|79|+0.010516|−0.021612|

C6 在这些组中的 LogLoss 均低于 C0。R4 在前五组的 LogLoss 低于 R1，在最高频组则更高。当前结果为低频收益提供描述性线索，但不是稳定性结论：没有分组置信区间或多种子结果，最高频组只有 38 个不同目标商品、79 个点击样本，不能预先归因其退步。

完整 C0/C6/C7/R1/R4 分组 AUC、LogLoss、输入校验和见[机器报告](../reports/frequency-diagnostic-v1.json)。这不是论文的 8/9 分位分组原样复现。

```powershell
python scripts/audit_frequency.py --store <feature-store> --items-dir <joined-exposures> --models <model-paths.json> --report <report.json>
```

模型清单为名称到验证预测 NPZ 路径的 JSON 映射。入口校验训练/验证曝光文件来源、全部预测行与标签，不访问测试集。

## 主表训练预算

核心预算范围：CIKM 的 C0/C2/C3/C5/C6/C7 与 MUSE 的 R0–R5，共 12 个配置；每个种子另计一次三轮 C1 MAKE 推荐预训练。预定种子为 42、2026、3407，数据划分种子保持不变。种子计划不等于这些运行已经完成。

依据已发布实测耗时：

|范围|纯训练时间|
|---|---:|
|1% 上述核心范围 × 3 种子|约 4.86 小时|
|5% 按实际训练行数比例线性外推|约 24.35 小时|
|线性值的 0.7–1.4 倍敏感性场景|约 17.04–34.09 小时|

敏感性范围是预算假设，不是统计区间或耗时保证。样本增长与词表增长不成比例，不能将显存直接乘五。预算不包括数据准备、验证与保存、MAKE 额外策略/轮数对照、历史长度扫描、DIN/SIM/TWIN/MISS 等补充基线、失败重跑，因此不是完整研究的总时间。

可追踪的逐项报告校验和、实测耗时与计算结果见[预算报告](../reports/study-budget-v1.json)。

```powershell

```

## 后续执行顺序

1. 完成 5% 属性、历史、多模态表示与训练词表构建，并检查嵌套关系、ID 对齐和覆盖率。
2. 使用代表性 C6 与完整 R4（L=1000）做至少 200 步资源与吞吐检查。采用分配显存不超过 9 GiB、工作集内存不超过 24 GiB 的工程目标，为 12 GiB GPU / 32 GiB RAM 留出余量；若不满足，重新选择批大小或更小子集并记录变化。
3. 根据实测更新预算，确认共同数据规模，再执行主表多种子验证与补充对照。不能根据某个子集上是否出现预期方法排名来选择数据规模。
4. 单列仍未完成的 MAKE 轮数网格、独立基线、长度扫描及分组稳定性；最后按冻结方案使用保留测试集。

本阶段记录时尚未启动 5% 模型训练。最新执行状态见阶段 16；仍未确定全量复现的可行性。
