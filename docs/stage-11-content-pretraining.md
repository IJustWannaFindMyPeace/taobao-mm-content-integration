# 内容分支与 MAKE 预训练

> 历史阶段记录：当前方法、三种子测试及方案定义见 [MAKE预训练与组合](make-integration.md)。本页早期设置、验证结果与当时待办不替代正式结论；零轮须区分随机冻结与随机联合。

## 研究问题与来源

本阶段检验固定内容向量的下游参数如何随训练轮数变化，为 MAKE 接入实验提供检查点。依据 [CIKM 2024 论文 §4.1 与 §4.3](https://arxiv.org/html/2407.19467v1#S4.SS3)，内容分支通过 CTR 任务训练，兴趣向量经过四层 MLP；后续将兴趣向量和中间输出接入 ID 模型。

C1 是内容分支诊断，不是完整 MAKE 融合实验。C4/C5 分别比较随机初始化联合训练与预训练后接入；二者尚未执行。

## 本项目结构适配

- 输入为固定 128 维 SCL 向量，反量化后做 L2 归一化，不训练图文编码器，不输入 ID 或用户属性。
- 使用最近 200 条历史；局部激活网络输入为 `[q, k, q-k, q*k]`，线性层宽度为 `512→80→40→1`，隐藏层使用 ReLU。
- 激活分数不做 softmax，直接对有效历史内容加权求和，得到 128 维兴趣向量。这是明确的 DIN 风格适配，不等同于现有 C0 的点积注意力。
- 四个线性层为 `128→128→64→32→1`，前三层后接 ReLU。预留兴趣向量与末个 32 维隐藏层供后续迁移。
- 历史 padding、缺失内容不参与聚合；目标内容缺失时兴趣为零，仍保留该样本并通过 MLP 偏置预测。

层宽、激活函数和中间层选择为本项目配置，不声称论文给出了这些细节。后续冻结策略也须单独标注。C1 与 C0 的输入和兴趣模块不同，曲线差异只能作为两种具体实现的诊断，不能单独归因为输入模态。

## 固定实验协议

使用现有 1% 用户子集，训练 609,902 条、验证 151,947 条。配置为 seed 42、batch 32、AdamW 学习率 0.001、无权重衰减、三轮训练。每轮重排训练数据；每轮完整验证并保存预测和模型。测试集不参与训练或检查点选择。

从仓库根目录执行，路径参数指向外部数据与产物目录：

```powershell
python scripts/train_content.py --store <feature-store> --config configs/c1.json --output-dir <fresh-run-directory>
python -m unittest discover -s tests
```

`--max-steps` 可用于部分训练资源检查，其报告不能当作完整轮数结果。模型检查点不包含优化器状态，不能用于精确断点续训。

## 验证与产物

实现已通过缺失目标、全空历史、padding 不变性、历史置换不变性、固定输入无梯度和参数梯度检查。完整测试集 27 项通过。

训练入口逐轮输出 `report.json`、`epoch-N.pt` 和 `validation-epoch-N.npz`，记录代码与输入清单 SHA256、完整验证指标、训练时长、显存峰值及重载误差。三轮运行已完成，结果见[机器报告](../reports/c1-seed42-epochs3.json)。

后续需要补齐 C0 同轮数诊断、多随机种子及融合对照。不得预设内容分支多轮必然改善，也不得用单种子结果确认工业场景的一轮过拟合现象。

## 三轮验证结果

|轮数|AUC|GAUC|LogLoss|训练秒数|
|---|---:|---:|---:|---:|
|1|0.598287|0.568083|0.390320|137.38|
|2|0.601184|0.571914|0.389781|136.38|
|3|0.600115|0.570949|0.390836|126.66|

训练合计约 400 秒，不含验证与保存；训练峰值分配显存 90.27 MiB，保留显存 104 MiB。此为 PyTorch 分配统计，不包含全部进程、驱动和 CPU 特征存储开销。全部检查点重载预测误差为零。

第二轮在三个验证指标上均优于第一轮；第三轮训练损失继续下降，但验证指标回落，因此本运行没有呈现单调改善。按预先采用的验证 GAUC 口径，三轮中第二轮最佳；保留全部检查点供轮数消融使用。单种子差异尚不能证明稳定收益，三轮结果也不能确定全局最优轮数。
