C6−C3 的平均 GAUC 增量为 0.005221，C6−C5 为 0.001322，三个种子中方向均为正，且各次按用户配对区间均高于零。C2 的 AUC/GAUC 在三个种子中均比 C0 高，但 LogLoss 均更差。C7 与 C6 的 GAUC 差值随种子改变方向，三个用户区间都跨零，且 C7 平均 LogLoss 更低，不能宣称 C6 全面胜出。

三种子样本标准差不是置信区间；用户 bootstrap 又以固定模型和人群为条件，不能将两种统计量混用。以上为同一验证人群的结果，未评估保留测试集，也未做多重比较校正。

汇总入口 `scripts/summarize_training_seeds.py` 必须接收三份完整运行目录、三份审计报告和三个独立内容预训练目录。入口验证每个种子的检查点选择及摘要绑定后，计算均值、样本标准差和同种子差值；不会选择最佳种子。

## 下一处证据缺口

核心表表明预训练冻结 MAKE 方案有收益，却不能单独判断收益来自预训练、冻结策略还是模型容量。1% 数据上已做过策略对照，但不能用它替代当前 5% 主实验的归因证据。

因此在 5% 数据、seed 42、历史 200 和相同优化器参数下补齐以下对照：

|初始化|内容分支是否冻结|配置|本轮处理|
|---|---|---|---|
|随机|否|C4|新增完整一轮|
|随机|是|C4-frozen|新增完整一轮|
|预训练|是|C5|复用已审计的 seed 42 核心结果|
|预训练|否|C5-joint|新增完整一轮|

预训练两组使用同一个 seed 42 第三轮检查点。固定冻结状态比较预训练收益，固定初始化比较冻结收益。C5−C0 本身不能替代这些控制变量比较。

同时运行 C0 三轮曲线，观察多轮训练与验证表现；其第一轮必须与原 C0 保存预测核对，防止比较基准漂移。C1 三轮曲线复用已审计结果。内容分支的其他预训练轮数网格仍未由这一实验覆盖。

```powershell
python scripts/run_make_study.py --store <store-050> --pretraining-run <seed42-content-run> --output-dir <fresh-directory> --supplement-only
```

队列按 C0 三轮、C4、C4-frozen、C5-joint 串行执行，已启动，尚无完整结果，预计约 4–5 小时。入口依据同一预训练报告选择检查点并保存最终配置快照；旧 1% 检查点不会被用于本轮。任一运行失败即停止后续任务。
