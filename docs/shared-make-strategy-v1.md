# 共同协议下的 MAKE 训练策略诊断

本阶段回答内容知识收益是否来自预训练初始化，以及预训练后冻结是否比继续训练更好。使用既定 5% 队列、seed=42、batch=256、两类学习率 0.001、L200，先进行单种子机制诊断，不宣称三种子策略结论。

## 四组策略

|初始化|内容知识分支冻结|内容知识分支继续训练|
|---|---|---|
|随机|随机冻结（新运行）|随机联合（新运行）|
|预训练|预训练冻结（已有核心 C5，后续审计对齐）|预训练联合（新运行）|

下游四组均一轮，相同主干和预算。预训练使用既有同种子三轮内容分支中验证 GAUC 最高的检查点（并列最早）；校验权重摘要，额外预训练成本单列。共享的是 CTR 内容分支知识，不是重新训练 SCL 编码器。

预定义比较：预训练冻结−随机冻结、预训练联合−随机联合，分别检查初始化；预训练联合−预训练冻结、随机联合−随机冻结，分别检查继续训练。不能只用两个同时改变初始化与冻结状态的模型解释单因素作用，也不能声称匹配了总计算量。

## 多轮 ID 诊断

另运行 ID 基线三轮，保留每轮训练与验证指标、预测和检查点。第一轮须与共同核心 ID 基线做逐预测一致性核验，后两轮才用于判断该协议下继续训练的变化。epochs=3 是本项研究变量，其他共同训练参数不变。即使验证后退，也不能推广成所有 ID 模型只能训练一轮。

## 执行与边界

入口 `run_make_study.py --supplement-only --protocol configs/shared-downstream-protocol-v1.json` 接受共同协议，保留显式诊断轮数，保存配置快照与协议摘要。四组新任务串行执行，训练后检查更新与重载；完整效果结论仍须后续预测审计。
