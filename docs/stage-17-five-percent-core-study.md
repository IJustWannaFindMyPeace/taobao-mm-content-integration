运行入口在启动前验证完整预训练、数据版本和检查点摘要，并保存最终配置快照；单卡串行执行，任一组失败即停止后续任务。

```powershell
python scripts/run_content_core.py --store <store-050> --content-run <c1-run> --hist-cache <cache-050> --output-dir <fresh-run-directory>
```

产物包括 `status.json`、六份配置快照、逐组日志、验证预测、模型检查点和完整报告。模型文件与逐样本预测留在数据工作目录，GitHub 发布汇总与可复现入口。

## 配对证据与局限

`scripts/audit_content_core.py` 验证六组公共配置、代码摘要、存储版本和全轮完成情况，逐条核对保存预测中的标签、源行与用户分组，重新计算指标，并核对 C5/C6 的检查点及 C3/C6 的缓存绑定。全部通过，见[审计与配对报告](../reports/content-core-050-audit.json)。

对验证用户进行 2,000 次配对 bootstrap（seed 2026），单标签用户保留在抽样总体中、GAUC 权重为零。下表为 GAUC 的绝对增量和 95% 百分位区间：

|---|---:|---|
|C2 − C0|0.005095|[0.003665, 0.006572]|
|C3 − C0|0.013678|[0.011977, 0.015434]|
|C5 − C0|0.016874|[0.014737, 0.019110]|
|C6 − C3|0.004524|[0.002697, 0.006286]|
|C6 − C5|0.001328|[0.000559, 0.002061]|
|C7 − C6|0.000398|[−0.001516, 0.002224]|

本轮支持 SimTier 和 MAKE 组合相对各单分支的 GAUC 收益，但 LogLoss 仍以 C3 最低。C2 排序指标改善而 LogLoss 恶化，说明多模态融合的收益依赖评价维度。C7 的 GAUC 点估计最高，但对 C6 的区间跨零，不能认定其稳定优于组合模型。

区间以固定模型和当前人群为条件，不涵盖训练随机种子、子集选择或检查点选择的不确定性，未做多重比较校正。MAKE 策略补充对照、其他种子、低频分组稳定性及保留测试评估仍未完成。MUSE 同规模核心训练与配对审计已完成，见[对应实验结果](https://github.com/IJustWannaFindMyPeace/taobao-mm-muse-repro/blob/main/docs/stage-05-five-percent-core-study.md)。两个项目的骨干与模块定义存在明确差异，跨项目数值不能直接用于单模块归因。
