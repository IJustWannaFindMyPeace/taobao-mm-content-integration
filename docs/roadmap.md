# 实施路线

两个项目围绕“痛点、改进、证据、局限”组织实验，阶段产物通过版本控制追踪。下表区分已经完成的工程检查与待完成的研究实验。

|阶段|交付物|验收条件|当前状态|
|---|---|---|---|
|0 · 环境|CUDA 诊断及环境记录|前后向、参数更新、保存重载通过|前序项目专用 Conda 环境、版本快照及 CUDA 检查通过|
|1 · 数据|来源清单、分片检查、正式子集协议|校验和、字段、ID 对齐、划分与覆盖可追踪|1% 子集的统一特征存储、训练词表与加载核验完成|
|2 · ID 基线|C0 训练入口与运行报告|映射与 mask 正确，loss 有限，重载一致|前序项目 C0 适配基线已完成单种子一轮训练与验证|
|3 · 评估|AUC、GAUC、LogLoss 与预测文件|不丢记录，完整用户聚合，并列处理正确|完整验证集指标与配对比较已执行；最终测试评估待进行|
|4 · 内容融合|C1、C2、C3、C7|同协议比较，明确表示与融合位置|C3 单种子对照完成；C1 单种子三轮验证完成；C2/C7 待实现|
|5 · MAKE|C4、C5、C6 及轮数诊断|结构对齐，预训练与冻结策略可追踪|四组双因素对照及 C0 三轮诊断完成，单种子验证结果已发布；C6 待实现|
|6 · 项目衔接|公共接口与来源版本|相同配置的迁移预测一致|待实现|
|7 · MUSE|R0–R5 与检索基线|固定公共分支，隔离检索和 ESU 改动|待实现|
